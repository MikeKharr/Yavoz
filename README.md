# Yavoz

Приложение на localhost: берёт `.xlsx` из каталога на Яндекс.Диске и кладёт рядом
копии с приставкой «обработано», заполнив в них два столбца.

- **U «Ссылка на подтверждение по запросу»** — формула поиска, та же, что в образце:
  `=HYPERLINK("https://yandex.ru/search/?text=" & B2 & " " & C2 & " " & D2 & " " & S2 & " " & T2)`
- **V «Ссылка на подтверждение в интернете»** — наиболее официальный найденный источник.

## Как выбирается источник для V

Оценка складывается из трёх независимых частей, и ни одна не решает сама:

| Часть | Что даёт вес | Что отнимает |
|---|---|---|
| Домен | `*.gov.ru`, `*.gosuslugi.ru`, `*.edu.ru`, `*.ac.ru`, `*.mil.ru` | соцсети, агрегаторы (`hh.ru`, справочники), новостные сайты |
| Путь | `/sveden`, `pedagogicheskiy-sostav`, `/struktura`, `/people`, `/kafedr`, `/sotrudniki` | — |
| Страница | фамилия, имя, отчество, слова должности, название организации в тексте | — |

Страница с правильным доменом, но без фамилии, проигрывает странице, где человек
и должность действительно названы. Верхние четыре кандидата дочитываются целиком,
остальные оцениваются по выдаче — читать все десять на каждую строку значит тысячи
загрузок на файл.

Уверенность пишется **примечанием к ячейке** V и в журнал прогона: в значении ячейки
она сломала бы ссылку, а соседние столбцы заняты данными.

- **высокая** — официальный домен или раздел о сотрудниках, фамилия и должность на странице;
- **средняя** — фамилия на странице и одно из двух;
- **низкая** — всё остальное. Ссылка всё равно записывается: пусть будет с пометкой,
  чем не будет вовсе.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env    # заполнить два доступа, см. ниже
.venv/bin/python -m yavoz
```

Открыть <http://127.0.0.1:8765>, указать путь каталога (`disk:/Верификация`) и нажать
«Обработать». Ход работы виден построчно.

## Доступы

Обязателен один — токен Яндекс.Диска:

| Переменная | Где взять |
|---|---|
| `YADISK_TOKEN` | <https://yandex.ru/dev/disk/poligon/> — кнопка «Получить OAuth-токен» |

`.env` в репозиторий не попадает (`.gitignore`).

## Откуда берётся выдача

Источник задаётся `YAVOZ_SEARCH`.

| Значение | Что это | Цена | Что нужно |
|---|---|---|---|
| `ddg` (по умолчанию) | метапоиск DuckDuckGo | бесплатно | ничего |
| `yandex` | Поисковый API в AI Studio | 0,488 ₽ за запрос, ≈58 ₽ на файл в 119 строк | ключ, идентификатор каталога, привязанная карта и роль `search-api.webSearch.user` у сервисного аккаунта |

Бесплатного тарифа у Яндекса нет: «бесплатность» — это стартовый грант 4000 ₽,
примерно 8200 запросов. Поэтому умолчание бесплатное.

**Проверено на строке из настоящего файла** (Беспалов, Курский государственный
университет, декан факультета): `ddg` вернул ожидаемую страницу
`kursksu.ru/people/view/316` **первой**, и оценка по адресу поставила её выше
всех — 28 баллов против 25 у следующей. Ранжирование делает этот код, поэтому
источник влияет на полноту выдачи, а не на качество выбора.

Частоту `ddg` прижимает сам, поэтому между запросами выдерживается пауза в две
секунды и на отказ делается три попытки. Файл в 119 строк из-за этого идёт
дольше — порядка получаса.

## Проверка доступа к Поисковому API Яндекса

Нужна только при `YAVOZ_SEARCH=yandex`:

```sh
.venv/bin/python tools/probe-search.py
```

Пробник берёт строку из настоящего файла и спрашивает оба эндпоинта Яндекса,
печатая коды ответов. `403` означает, что ключ верен, а роли нет.

## Что делается с файлом

Читается только то, на что можно опереться: столбцы **B, C, D** (ФИО), **S** (место
работы), **T** (должность). Остальные столбцы могут быть пустыми — на них ничего не
завязано. Лист данных определяется по шапке: тот, где в `B1` стоит «Фамилия»; если
таких несколько, берётся самый длинный.

Строки, где **V уже заполнен**, пропускаются: поиск по ним не тратится, значение не
затирается, в журнале остаётся пометка. Столбец U заполняется, если он пуст.

## Проверки данных: почему здесь отдельный код

`openpyxl` — единственная удобная библиотека для `.xlsx`, но при сохранении она
**молча выбрасывает выпадающие списки** (расширенные проверки данных `x14`). На
рабочем файле это 5 проверок на листе «БД в работе» — лист ими и живёт.

Поэтому после сохранения блок проверок переносится из исходной книги в новую
(`yavoz/preserve.py`), а тест `test_выпадающие_списки_переживают_обработку` краснеет,
если этот перенос убрать. Проверено мутацией, а не обещанием.

## Тесты

```sh
.venv/bin/python -m unittest discover -s tests -t .
```

21 тест, сети не требуют: поиск и загрузка страниц подменяются заглушками.
Три мутации прогнаны и красные: снятие переноса проверок, запись поверх заполненного
V, снятие примечания с уверенностью.

## Что не проверено

1. **Бесплатный источник на объёме.** Проверен **одной** строкой из настоящего
   файла: ожидаемая страница пришла первой. Как он держится на 119 запросах
   подряд и не начнёт ли прижимать частоту сильнее паузы в две секунды —
   покажет первый полный прогон.
2. **Живой Поисковый API Яндекса.** Форма запроса написана по документации и
   разобрана на образце ответа; на живом ключе получен `403` — ключ верен, роли
   `search-api.webSearch.user` у сервисного аккаунта нет. То есть **тело запроса
   так и не проверено**: до него дело не дошло.
3. **Живой Яндекс.Диск.** Перечисление, скачивание и загрузка написаны по
   документации REST API. На подставном токене Диск ответил `401`, то есть адрес
   и форма авторизации верные; всё остальное на настоящем токене не гонялось.
4. **Качество выбора источника на объёме.** Правила выведены из четырёх примеров
   обработанного файла и подтверждены на одной строке. Насколько они верны на
   всех 119 — покажет колонка уверенности в журнале.
5. **Другие расширения Excel.** Возвращаются проверки данных. Если в каком-то
   файле есть срезы, спарклайны или условное форматирование из расширения `x14`,
   они `openpyxl` тоже теряются, и этот код их пока не возвращает.
6. **Скорость.** На строку приходится один поисковый запрос, пауза в две секунды
   и до четырёх загрузок страниц. Для файла в 119 строк это порядка получаса,
   оценка грубая.
